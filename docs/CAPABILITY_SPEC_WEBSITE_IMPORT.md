# Capability Spec: Website Import

## Purpose

Website Import converts a public web page at a selected viewport into editable Figma layers using Design IR generated by the Parser Server.

## User Input

- URL.
- Viewport preset, MVP default Desktop.
- Capture height or first viewport.
- Options: include images, exclude hidden elements, max depth, max node count.

Current runtime placeholder accepts only:

```ts
{ url: string }
```

The URL must be a syntactically valid HTTPS URL. The capability does not fetch the URL in the runtime foundation step.

## Validation

Validation checks:

- URL format.
- Allowed scheme: `https` in MVP.
- Parser Server availability.
- Viewport validity.
- Max height and node limits.

Server-side validation is authoritative. Parser Server rejects unsafe protocols, embedded credentials, localhost, private or link-local IPs, metadata endpoints, DNS failures, mixed public/private DNS results, and unsafe redirects before browser navigation.

## Preview

Preview returns:

- Final URL.
- Page title.
- Viewport.
- Estimated node count.
- Layout summary.
- Font summary.
- Asset summary.
- Unsupported CSS warnings.
- Security warnings.

Preview creates no Figma nodes.

## Execute

Future execution:

1. Request full IR from Parser Server.
2. Validate IR version.
3. Load required fonts through Font Loader.
4. Resolve image bytes or server-provided asset references.
5. Convert IR into node mutation operations.
6. Execute mutations in chunks.
7. Select created root frame.
8. Record history.
9. Return result.

Current placeholder execution returns `NOT_IMPLEMENTED` without network access.

Parser Server provides `POST /v1/imports/analyze`, which returns a versioned `GEOMETRY_CAPTURED` response after request schema validation, target security validation, safe Chromium navigation, DOM Snapshot, Style Snapshot, and Geometry Evidence extraction. Design IR generation and Figma rendering remain unimplemented.

Safe browser request guarding validates main documents, redirects, and subresources before extraction. Geometry Evidence remains factual only; layout inference and Figma mapping are later stages.

## Progress

Progress phases:

- `VALIDATING`
- `FETCHING`
- `PARSING`
- `NORMALIZING`
- `LOADING_FONTS`
- `CREATING_NODES`
- `APPLYING_ASSETS`
- `RECORDING_HISTORY`
- `COMPLETE`

## Result

Result includes common counts and Website Import details:

- Root frame ID.
- Created node IDs.
- Font substitutions.
- Asset failures.
- Unsupported CSS warnings.
- Raster fallback count.
- Component candidate summary.

## Failure

Failures should be typed:

- Invalid URL.
- Blocked URL.
- Parser timeout.
- Page load failure.
- IR validation failure.
- Font load failure.
- Asset failure.
- Render failure.

Partial failure is allowed when individual assets or nodes fail.

## Cancel

Cancellation uses an operation ID and abort signal. Parser requests should be cancellable where possible. Main-thread rendering checks cancellation between chunks.

## History

History records operation metadata and generated root node. MVP restore removes generated nodes. If generated nodes were edited after import, restore should confirm or report that nodes changed since creation.

## Settings

MVP settings:

- Parser Server URL.
- Default viewport.
- Default max height.
- Font mappings.
- Import limits.

## Security

Website Import must not bypass authentication or private network access. Parser Server blocks local, private, link-local, and metadata endpoints and sanitizes SVG/assets.

The Plugin must not directly fetch external website HTML, iframe external pages, inspect cross-origin DOM, or proxy external images.

## Completion Criteria

MVP is complete when a controlled fixture page with header, hero, button, image, three cards, and footer imports into a root Figma frame with editable text, image paints, Auto Layout for flex containers, result report, selection, history, and remove/restore.
